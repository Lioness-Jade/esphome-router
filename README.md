# 📡 ESP32 NAT/AP Bridge ESPHome Component (Mini Router)

This project transforms an ESP32 device into a Wi-Fi Access Point (AP) supporting Network Address Translation (NAT) / bridging functionality, acting as a mini router, configurable directly from ESPHome. Implemented as an external component, it integrates cleanly and declaratively into your YAML configuration.

---

## 📝 Overview

This custom external component for ESPHome allows your ESP32 to create its own local Wi-Fi network (AP) while connecting to an existing Wi-Fi network (Station or STA mode). Devices connected to the ESP32 AP can access the internet through the ESP32's STA connection, thanks to the implementation of NAT (Network Address Translation). It also provides the ability to configure port forwarding to expose internal services to the external network.

**Bridging functionality is fully implemented**: When bridge mode is enabled, the ESP32 works like a true router relay, ensuring all types of IP packets (ICMP, TCP, UDP, etc.) are correctly forwarded, achieving transparent network bridging.

---

## ✨ Key Features

### Core Network Functions

* **Configurable Wi-Fi Access Point (AP):** Define the SSID, password, and visibility (hidden/visible) of the Wi-Fi network created by the ESP32.

* **ESPHome-Managed Station Mode (STA):** The ESP32 connects as a standard client to your main Wi-Fi network, with Wi-Fi settings managed by ESPHome.

* **Network Address Translation (NAT):** Devices on the AP network can access the internet through the ESP32's STA connection.

* **Full Bridge Mode:** ✅ **Implemented** - When enabled, calls `ip_forward_enable(1)` to ensure complete IP packet forwarding, identical to a router relay function, supporting all protocols including ICMP, TCP, UDP, etc.

* **Port Forwarding:** Configure rules to redirect incoming traffic from the main network to specific devices on the AP internal network.

* **Customizable AP Internal IP:** Define the IP address of the Wi-Fi network generated by the ESP32 directly from YAML configuration (e.g., `192.168.10.1`).

### HomeAssistant Sensor Integration

#### Numeric Sensors
- **upload_speed**: Upload speed in Mbps (megabits per second)
- **download_speed**: Download speed in Mbps (megabits per second)
- **connected_devices**: Number of devices currently connected to the AP
- **gateway_health**: Gateway health status (1=online, 0=offline), checked every 5 seconds
- **forward_throughput**: Forwarding throughput in packets/second
- **sta_link_rate**: STA link rate in Mbps (estimated based on signal quality)
- **sta_channel**: Wi-Fi channel the STA is connected to

#### Text Sensors
- **client_mac_list**: List of MAC addresses of all clients currently connected to the AP, separated by semicolons
- **online_status**: Online status text ("Online" or "Offline")

### Other Features

* **Online Detection:** Checks gateway health status every 5 seconds to ensure network connectivity is normal

* **STA Connection Info:** Provides STA link rate and channel information for the AP device

* **NAT/Bridge Client Monitoring:** Real-time display of connected device count and MAC address list

* **Bridge Forwarding Throughput Count:** Real-time monitoring of packet forwarding rate (packets/second)

* **No Flash Writes:** All statistics are calculated in memory only, without writing to Flash, extending device lifespan

* **Based on ESP-IDF 5.1.6:** Uses the latest ESP-IDF APIs and features for a robust and modern implementation.

* **Efficient Data Transfer:** Optimized algorithms ensure high data transfer efficiency with minimal impact on device resources

## 🚀 ESPHome Minimal Configuration

To use this component, you must add it as an "external_components":

```yaml
external_components:
  - source:
      type: git
      url: https://github.com/Lioness-Jade/esphome-router
    components: nat_ap
    refresh: always
```

Configuration example:

```yaml
external_components:
  - source:
      type: git
      url: https://github.com/Lioness-Jade/esphome-router
    components: nat_ap
    refresh: always

esphome:
  name: esp32-c3-nat
  friendly_name: esp32-c3-nat

esp32:
  board: esp32-c3-devkitm-1
  cpu_frequency: 160MHZ
  framework:
    type: esp-idf

logger:
  level: DEBUG

api:
  encryption:
    key: ""
  reboot_timeout: 0s

ota:
  - platform: esphome
    password: ""

wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password

nat_ap:
  ap_ssid: "ESPHomeNATAP"            # AP SSID name
  ap_password: "ESPHomeNATAP"        # AP password
  ap_ip_address: "192.168.10.1"      # IP provided by AP to clients
  hide_ssid: true                    # true/false to enable/disable SSID broadcast
  bridge_mode: true                  # Enable bridge mode for complete IP packet forwarding (like router relay)

  # HomeAssistant numeric sensor configuration
  sensors:
    upload_speed:
      name: "NAT AP Upload Speed"
    download_speed:
      name: "NAT AP Download Speed"
    connected_devices:
      name: "NAT AP Connected Devices"
    gateway_health:
      name: "NAT AP Gateway Health"
    forward_throughput:
      name: "NAT AP Forward Throughput"
    sta_link_rate:
      name: "NAT AP STA Link Rate"
    sta_channel:
      name: "NAT AP STA Channel"

  # HomeAssistant text sensor configuration
  text_sensors:
    client_mac_list:
      name: "NAT AP Client MAC List"
    online_status:
      name: "NAT AP Online Status"

  port_forwarding:
    - protocol: TCP                  # API
      external_port: 10001           # Port for HomeAssistant or esphome to search redirected device
      internal_ip: "192.168.10.2"    # Client IP to redirect port to (another esphome device)
      internal_port: 9001            # API port of another esphome device
    - protocol: TCP                  # OTA
      external_port: 10002           # Port for esphome to search redirected device
      internal_ip: "192.168.10.2"    # Client IP to redirect port to (another esphome device)
      internal_port: 9002            # OTA port of another esphome device
    - protocol: UDP
      external_port: 12345
      internal_ip: "192.168.10.2"
      internal_port: 12345
```

Another esphome device connected to esp32-c3-nat AP:

```yaml
esphome:
  name: esp32-c3
  friendly_name: esp32-c3

esp32:
  board: esp32-c3-devkitm-1
  cpu_frequency: 160MHZ
  framework:
    type: esp-idf

logger:
  level: DEBUG

api:
  encryption:
    key: ""
  port: 9001

ota:
  - platform: esphome
    password: ""
    port: 9002

wifi:
  ssid: ESPHomeNATAP
  password: ESPHomeNATAP
  use_address: ""                     # IP assigned to esp32-c3-nat by your router
  manual_ip:
    gateway: "192.168.10.1"           # esp32-c3-nat gateway (IP provided by AP to clients)
    static_ip: "192.168.10.2"         # IP to assign to this esp32 (within esp32-c3-nat network)
    subnet: 255.255.255.0
  fast_connect: true
```

Tested to cascade connect up to 10 ESP32s (reference fran6120/esphome-nat-ap), with latency to the last ESP32 less than 1 second.

Even OTA updates work correctly, although latency will be more noticeable.

## 🌉 Bridge Functionality Guide

### What is Bridge Mode?

When Bridge Mode is enabled, the ESP32 operates as a transparent network bridge, similar to a router's relay mode. Unlike standard NAT mode, bridge mode ensures **all types of IP packets** (ICMP, TCP, UDP, etc.) are correctly forwarded, achieving true network transparent bridging.

### Enabling Bridge Mode

Add or set `bridge_mode: true` in the `nat_ap` configuration:

```yaml
nat_ap:
  ap_ssid: "ESPHomeNATAP"
  ap_password: "ESPHomeNATAP"
  ap_ip_address: "192.168.10.1"
  bridge_mode: true  # ← Enable bridge mode
```

### Bridge Mode vs NAT Mode

| Feature | NAT Mode (Default) | Bridge Mode |
|------|----------------|----------|
| IP Forwarding | TCP/UDP only | ✅ All protocols (ICMP, TCP, UDP, etc.) |
| Network Transparency | Requires address translation | ✅ Fully transparent |
| Ping Test | May be limited | ✅ Fully supported |
| Use Case | General internet access | Scenarios requiring full network functionality |

### How It Works

When `bridge_mode: true`, the system automatically calls `ip_forward_enable(1)` to enable kernel-level IP packet forwarding, ensuring:

1. **ICMP Packet Forwarding**: Supports network diagnostic tools like ping
2. **Complete TCP/UDP Forwarding**: All ports and protocols communicate normally
3. **Transparent Bridging**: Client devices feel like they're directly connected to the main network

### Verifying Bridge Functionality

After enabling bridge mode, you can:

1. **Ping Test**: Ping devices in the main network from AP clients
   ```bash
   ping 192.168.1.1  # Main network gateway
   ```

2. **Access Main Network Services**: AP clients can directly access servers, printers, etc. in the main network

3. **Monitor Forwarding Throughput**: View real-time forwarding data via HomeAssistant sensors
   - `forward_throughput`: Shows number of packets forwarded per second
   - `upload_speed` / `download_speed`: Shows bridge data transfer rates

### Notes

- Bridge mode slightly increases CPU usage as more types of network packets need to be processed
- Ensure stable ESP32 STA connection for optimal bridge performance
- In bridge mode, AP clients still use IP addresses from the segment configured in `ap_ip_address`
- All statistics are calculated in memory only, without writing to Flash, not affecting device lifespan

### Example Configuration (Complete)

```yaml
nat_ap:
  ap_ssid: "ESPHomeNATAP"
  ap_password: "ESPHomeNATAP"
  ap_ip_address: "192.168.10.1"
  hide_ssid: false
  bridge_mode: true  # Enable full bridge functionality

  sensors:
    forward_throughput:
      name: "Bridge Forward Throughput"
    upload_speed:
      name: "Bridge Upload Speed"
    download_speed:
      name: "Bridge Download Speed"
    connected_devices:
      name: "Bridge Client Count"
```

## 📊 Sensor Descriptions

### Numeric Sensors
- **upload_speed**: Upload speed in Mbps (megabits per second), real-time monitoring of NAT/bridge forwarding data rate
- **download_speed**: Download speed in Mbps (megabits per second), real-time monitoring of NAT/bridge forwarding data rate
- **connected_devices**: Number of devices currently connected to the AP, NAT/bridge client count
- **gateway_health**: Gateway health status (1=online, 0=offline), checked every 5 seconds for online detection
- **forward_throughput**: Forwarding throughput in packets/second, bridge forwarding throughput count
- **sta_link_rate**: STA link rate in Mbps, provides STA link rate information for the AP device
- **sta_channel**: Wi-Fi channel the STA is connected to, provides STA channel information for the AP device

### Text Sensors
- **client_mac_list**: List of MAC addresses of all clients currently connected to the AP, separated by semicolons, NAT/bridge client MAC list
- **online_status**: Online status text ("Online" or "Offline"), gateway resource health status indicator

These sensors update every second (gateway health status updates every 5 seconds) and can be used in HomeAssistant to create dashboards, automations, etc. All data is calculated in memory only, without writing to Flash.

## 🔧 Troubleshooting

1. **NAT not working**: Ensure STA has successfully connected to the main Wi-Fi and obtained an IP address
2. **Port forwarding not taking effect**: Check if the internal IP address is correct and ensure the target device is online
3. **Bridge mode issues**: After enabling bridge mode, the system automatically calls `ip_forward_enable(1)` to ensure complete IP packet forwarding
4. **No sensor data**: Ensure corresponding sensors are enabled in the configuration
5. **MAC list is empty**: Ensure devices are connected to the AP
6. **Forwarding throughput is 0**: Ensure devices are communicating through the ESP32
7. **Gateway health shows offline**: Check if STA has obtained a valid IP address and gateway
8. **Ping not working in bridge mode**: Confirm `bridge_mode: true` is set and check firewall settings
